# 记忆系统深度解析

本文档详细拆解 OpenClaw Lite 中"记忆"的实现思路，涵盖短期记忆、长期记忆、压缩的完整链路。

## 为什么 Agent 需要记忆

LLM 本身是无状态的。每次调用 API，它只能看到你传入的 messages 列表，对之前的对话一无所知。
所谓"记忆"，就是我们在每次调用前，把历史消息塞回 messages 列表里，让 LLM 以为它"记得"之前的对话。

这带来一个核心矛盾：历史越长，上下文越丰富，但 token 消耗越大，最终会撞上 context window 上限。
整个记忆系统的设计，就是在"记得多"和"装得下"之间找平衡。

## 记忆的四层架构

```
┌─────────────────────────────────────────────┐
│  Layer 4: System Prompt（身份 + 工作区上下文）  │  ← 每次都注入，永不压缩
├─────────────────────────────────────────────┤
│  Layer 3: Long-Term Memory（跨会话长期记忆）   │  ← 用户画像 + 知识记忆
├─────────────────────────────────────────────┤
│  Layer 2: Compacted History（压缩摘要）       │  ← 旧消息的 LLM 生成摘要
├─────────────────────────────────────────────┤
│  Layer 1: Recent Messages（最近的原始消息）    │  ← 最近 N 条完整保留
└─────────────────────────────────────────────┘
```

四层从上到下，优先级递减，但都会被拼进发给 LLM 的 messages 列表。


## Layer 1: 原始消息存储 (`session.py`)

### 数据模型

每条消息是一个 `Message` dataclass：

```python
@dataclass
class Message:
    role: str          # "user" | "assistant" | "system" | "tool"
    content: str       # 消息正文
    timestamp: float   # Unix 时间戳，自动生成
    tool_call_id: str  # 工具调用关联 ID（仅 tool 消息）
    name: str          # 工具名称（仅 tool 消息）
```

### 持久化机制

`SessionStore` 将会话序列化为 JSON 文件（默认 `~/.openclaw-lite/sessions.json`）。
写入采用"写临时文件 → 原子替换"策略，防止崩溃导致数据损坏。

### 历史裁剪

加载历史时有 `history_limit`（默认 50），超出直接丢弃最早的消息。
这是最粗暴的记忆管理，真正精细的处理在 compaction 和长期记忆。


## Layer 2: 历史压缩 (`compaction.py`)

当会话消息数超过阈值（默认 40 条）时，自动压缩旧消息：

1. 保留最近 10 条消息不动
2. 将更早的消息用 LLM 生成一段摘要
3. 摘要保留关键信息：用户请求、决策结论、文件路径、错误和修复记录
4. 用一条 assistant 消息替换所有旧消息

```
压缩前（45 条消息）：
[msg1, msg2, ..., msg35] [msg36, msg37, ..., msg45]
 ←——— 旧消息（35条）——→  ←—— 最近消息（10条）——→

压缩后（11 条消息）：
[摘要消息] [msg36, msg37, ..., msg45]
```

压缩失败时保留原始历史，不会丢数据。


## Layer 3: 长期记忆 (`memory.py`) — 核心设计

长期记忆是跨会话的持久化存储，reset 会话不会丢失。
存储为两个独立文件：
- `user_profile.json` — 用户画像（偏好 + 事实）
- `memories.json` — 知识记忆条目

### 三层写入策略

长期记忆的写入不是每轮都调 LLM，而是分三个层级，按成本从低到高：

```
用户消息进来
  ├── 层级 1 - 显式记忆: /remember 命令 → 直接存入（零成本）
  ├── 层级 2 - 实时检测: 正则规则扫描 → 命中则存入（零成本）
  └── 层级 3 - 批量提取: 每 10 轮或 reset → 调 LLM 提取（有成本）
```

#### 层级 1: 显式记忆（`/remember` 命令）

用户主动说"记住这个"，直接写入，零歧义零成本。

```
你> /remember 我叫斯嘉丽·约翰逊
  🧠 已记住: 我叫斯嘉丽·约翰逊
```

内容同时存入 `memories.json` 和 `user_profile.json`。
如果正则规则能识别出分类（如"我叫xxx" → 身份事实），会自动归类。


#### 层级 2: 实时检测（规则引擎）

每条用户消息都会经过一组正则规则扫描，不调用 LLM，纯本地匹配：

```python
DETECTION_RULES = [
    (r"我(?:叫|是|名字是)\s*(.+)", "fact", ["身份"]),
    (r"我(?:用|使用)\s*(.+?)(?:开发|编程)", "fact", ["技术栈"]),
    (r"(?:请)?用(中文|英文)(?:回复)?", "preference", ["语言"]),
    (r"我(?:喜欢|偏好)(.+?)(?:的)?(?:回复|风格)", "preference", ["风格"]),
    # ...更多规则
]
```

匹配到的信息自动分类存入画像：
- `fact` → `user_profile.facts`（如"斯嘉丽·约翰逊"、"Python 3.12"）
- `preference` → `user_profile.preferences`（如"简短回复"、"中文"）

优点：零延迟、零成本、确定性强
缺点：只能捕获预定义的模式，复杂语义理解不了

#### 层级 3: 批量提取（LLM）

每 10 轮对话或会话 reset 时，调用 LLM 分析最近 20 条消息，提取：
- 用户偏好（回复风格、语言等）
- 用户事实（姓名、技术栈、项目信息等）
- 重要事件（做了什么决策、改了什么文件等）

这是最强大但最贵的方式，通过控制频率来摊薄成本。


### 记忆检索

查询时使用关键词匹配 + 时间衰减评分：

```
总分 = 关键词匹配分 + 标签匹配分 × 2 + 时间衰减分
时间衰减 = 1 / (1 + 天数 / 7)  // 半衰期 7 天
```

按总分排序，取 top-5 注入 system prompt。
生产环境应替换为向量相似度检索（如 embedding + cosine similarity）。

### 记忆注入

每次对话开始时，`format_for_prompt()` 将长期记忆格式化为文本，注入 system prompt：

```
## 用户画像（长期记忆）
偏好：
- 简短回复
- 中文交流
已知信息：
- 斯嘉丽·约翰逊
- 使用 Python 3.12

## 相关历史记忆
- 上次修改了 config.json 的模型配置
- 项目使用 qwen-max 作为主模型
```

## Layer 4: System Prompt 中的持久上下文

System prompt 是每次对话都会注入的"永久记忆"，不受压缩影响。
包含身份信息、工具描述、安全规则，以及工作区上下文文件（SOUL.md 等）。
这些是人工编写的静态知识，不从对话中学习。


## 完整的记忆生命周期

```
1. 用户输入 "我叫斯嘉丽，帮我改一下 config.json"
   ↓
2. 实时检测: 正则匹配到 "我叫斯嘉丽" → 存入 profile.facts
   ↓
3. SessionStore 加载历史 + LongTermMemory 格式化长期记忆
   ↓
4. build_system_prompt() 拼装:
   [system_prompt + 长期记忆 + 工作区上下文]
   ↓
5. should_compact() 检查是否需要压缩
   ↓
6. Agent 循环: LLM 调用 → 工具执行 → 结果回传
   ↓
7. 保存 assistant 回复到 SessionStore
   ↓
8. should_batch_extract() 检查是否到了批量提取时机
   ├── 是 → 调 LLM 提取记忆，重置计数器
   └── 否 → 跳过
```

## 用户命令

| 命令 | 说明 |
|------|------|
| `/remember <文本>` | 主动记住一条信息 |
| `/memory` | 查看当前所有长期记忆 |
| `/new` `/reset` | 重置会话（会先提取长期记忆再清空） |

## 存储文件

```
~/.openclaw-lite/
├── sessions.json        # 会话历史（会话级，reset 会清空）
├── user_profile.json    # 用户画像（永久，reset 不影响）
└── memories.json        # 知识记忆（永久，reset 不影响）
```
